# DashScope realtime ASR：端点/静音窗实测

> 2026-11-18 用真机档案 `20261117-221010-..._46019`（122.8 s / 13 句）原速重放测的。
> 探针：`bench/latency/probe-realtime-asr-silence.mjs`（参数收不收）、
> `bench/latency/probe-realtime-asr-events.mjs`（客户端事件）、
> `bench/latency/probe-realtime-asr-turn.mjs`（真实行为与延迟）。
> 客户端实现：`src/qwen-realtime-asr.ts`。

## 1. 结论速览

| 问题 | 答案 |
|---|---|
| `silence_duration_ms` 能不能 <200 | **能填，但不生效**（下面的「回声」） |
| 文档写的范围 | `[200, 6000]`，默认 800，推荐 400 —— 200 是硬下限 |
| 想真的比 200 更快 | 只能 `turn_detection: null` + 自己 `input_audio_buffer.commit` |
| commit → 定稿 | **中位 261 ms**（13 句，停嘴 +40 发）/ 299（停嘴 +0 发） |
| VAD 模式 `speech_stopped` → 定稿 | 139–204 ms（**比手动快**，因为它早就边听边解码了） |
| 空缓冲 commit | 报 `maybe no invalid audio stream`，必须有脏标记 |
| `input_audio_buffer.clear` | **不存在**（`invalid_value`）→ 打断只能 commit 后扔结果 |
| 空闲会不会被关 | 一条连接挂 90 s 不关（NLS 会 `IDLE_TIMEOUT`） |
| 计费 | 按音频秒，`qwen3-asr-flash-realtime` 0.00033 元/秒 |

## 2. 回声：`session.updated` 不是承诺

把 `silence_duration_ms` 依次报 800/500/200/150/100/50/0，`session.updated` **每次都原样回**。
但同一段音频上量服务端 VAD 的判停时刻：

| 报的窗 | 判停时刻（ms，四句） |
|---|---|
| 800 | 2106 / 7200 / 17598 / 29520 |
| **200** | 1602 / 5887 / 17158 / 29094 |
| 150 | 1588 / 5846 / 17139 / 29068 |
| 100 | 1601 / 5869 / 17137 / 29089 |

200/150/100 三档**重合在 ±13 ms** → 内部静默夹在 200。**别信回执，要计时。**
（`type: semantic_vad` 同样被接受、同样回 800 —— 纯 ASR 模型也不支持它。）

## 3. 事件字段（照实测，别照文档猜）

```
.text      → { text: "", stash: "嗯，见面了", language: "zh", emotion: "neutral" }
.completed → { transcript: "嗯，见面了。", language, emotion, usage: { duration: 4, ... } }
```

增量在 **`stash`**，`text` 恒为空串 —— 拿 `text` 当增量会永远是空的。

## 4. 手动 commit 的表现（真机音频，13 句）

| 做法 | commit → 定稿 |
|---|---|
| 停嘴 +40 ms 发 commit | 213 / 262 / 279 / 241 / 310 / 301 / 237 / 261 / 306 / 241 / 254 / 260 / 323（中位 261） |
| 停嘴 +0 ms 发 commit | 178 … 404（中位 299，和 +40 同分布） |

四句关键句在 +0/+40 都**没有截尾**（含「见面了」「《星球大战》」）。上一版「必须 +120 ms 才不丢尾字」
的结论在**这段音频**上复现不出来 —— 样本只有 13 句，不能当结论用。

## 5. 接进编排层之后的实测（`bench/replay/run.py`，同一场 13 轮）

`MIAI_STT=qwen-realtime`，`VOICE_COMMIT_MS` 换值；① = 停嘴→出句。

| 配置 | ① 中位 | 轮数 | 结构 |
|---|---:|---|---|
| NLS（现网） | 400 | 13 | 基线 |
| qwen + commit **120** | **351** | 12 | 不拆句；文本保真（只差标点、1 处「我」） |
| qwen + commit **40** | **301** | 13 | 一句被拆成两轮（「对吗？」+「那句。」）→ 触发打断 + 续话 |

**40 ms 的代价**：`对吗？` 与 `那句。` 之间的换气 >40 ms，被当成句尾，判停当场给了 0.661
就收下 —— 于是先答了半句、刚出声就被后半句打断（`打断 听到定稿 → 停止播放`、
`续话 被打断，剩 9 字没说完`）。**文本没丢**，代价是白起一轮 + 一次打断。
120 ms 能把这一刀挡在窗外。

**⚠️ 回归脚本的坑（已修）**：`parse()` 原来取的是这一轮**最后一条** `asr.sentence`。
客户端控端点之后一句话会被切成好几段，只取最后一段会把整句读成半句 —— 看着像
「句首丢了」（「台词的经典是」不见了），其实组装器早就拼成
`台词的经典是。台词是什么来着？` 派出去了（见 `harness.log` 的 `文本` 行）。
现在改成把这一轮的全部片段按序拼接。

**回放噪声**：③（开轮→首块）在 NLS 基线上同样出现 12202 / 11408 的长尾，② 也有 4526 ——
那是回放环境的，不是本改动引入的。
