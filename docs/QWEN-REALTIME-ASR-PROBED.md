# DashScope realtime ASR：端点/静音窗实测

> 2026-11-18 用真机档案 `20261117-221010-..._46019`（122.8 s / 13 句）原速重放测的。
> 探针：`bench/latency/probe-realtime-asr-silence.mjs`（参数收不收）、
> `bench/latency/probe-realtime-asr-events.mjs`（客户端事件）、
> `bench/latency/probe-realtime-asr-turn.mjs`（真实行为与延迟）。
> 客户端实现：`src/qwen-realtime-asr.ts`。

## 1. 结论速览

| 问题 | 答案 |
|---|---|
| `silence_duration_ms` 能不能 <200 | **能填，但不生效**（下面的「回声」） |
| 文档写的范围 | `[200, 6000]`，默认 800，推荐 400 —— 200 是硬下限 |
| 想真的比 200 更快 | 只能 `turn_detection: null` + 自己 `input_audio_buffer.commit` |
| commit → 定稿 | **中位 261 ms**（13 句，停嘴 +40 发）/ 299（停嘴 +0 发） |
| VAD 模式 `speech_stopped` → 定稿 | 139–204 ms（**比手动快**，因为它早就边听边解码了） |
| 空缓冲 commit | 报 `maybe no invalid audio stream`，必须有脏标记 |
| `input_audio_buffer.clear` | **不存在**（`invalid_value`）→ 打断只能 commit 后扔结果 |
| 空闲会不会被关 | 一条连接挂 90 s 不关（NLS 会 `IDLE_TIMEOUT`） |
| 计费 | 按音频秒，`qwen3-asr-flash-realtime` 0.00033 元/秒 |

## 2. 回声：`session.updated` 不是承诺

把 `silence_duration_ms` 依次报 800/500/200/150/100/50/0，`session.updated` **每次都原样回**。
但同一段音频上量服务端 VAD 的判停时刻：

| 报的窗 | 判停时刻（ms，四句） |
|---|---|
| 800 | 2106 / 7200 / 17598 / 29520 |
| **200** | 1602 / 5887 / 17158 / 29094 |
| 150 | 1588 / 5846 / 17139 / 29068 |
| 100 | 1601 / 5869 / 17137 / 29089 |

200/150/100 三档**重合在 ±13 ms** → 内部静默夹在 200。**别信回执，要计时。**
（`type: semantic_vad` 同样被接受、同样回 800 —— 纯 ASR 模型也不支持它。）

## 3. 事件字段（照实测，别照文档猜）

```
.text      → { text: "", stash: "嗯，见面了", language: "zh", emotion: "neutral" }
.completed → { transcript: "嗯，见面了。", language, emotion, usage: { duration: 4, ... } }
```

增量在 **`stash`**，`text` 恒为空串 —— 拿 `text` 当增量会永远是空的。

## 4. 手动 commit 的表现（真机音频，13 句）

| 做法 | commit → 定稿 |
|---|---|
| 停嘴 +40 ms 发 commit | 213 / 262 / 279 / 241 / 310 / 301 / 237 / 261 / 306 / 241 / 254 / 260 / 323（中位 261） |
| 停嘴 +0 ms 发 commit | 178 … 404（中位 299，和 +40 同分布） |

四句关键句在 +0/+40 都**没有截尾**（含「见面了」「《星球大战》」）。上一版「必须 +120 ms 才不丢尾字」
的结论在**这段音频**上复现不出来 —— 样本只有 13 句，不能当结论用。

## 5. 接进编排层之后的实测（`bench/replay/run.py`，同一场 13 轮）

`MIAI_STT=qwen-realtime`，① = 停嘴→出句。

| 配置 | ① p50 | 有声拆句¹ | 无声拆句² | 备注 |
|---|---:|---|---|---|
| NLS（现网） | 400 | 0 | 0 | 13 轮 |
| commit 40，**无开轮门槛** | 301 | **1** | 0 | 「对吗？」先答了半句，后面被打断 |
| commit 40 + 门槛 **300/200** | **254 / 261** | **0** | 0 / 1 | 两次跑；文本保真 |
| commit 60 + 门槛 300/200 | 338 | 0 | 1 | 单次跑 |
| commit 40 + 门槛 400/250 | 337 | 0 | 1 | **过度合并**：四段并成一句，还多等 1.3 s |

¹ 拆出来的碎片**已经出声**（用户听到回答又被打断）—— 真损失。
² 首块音频前就被取消，用户无感。

**开轮门槛（`VOICE_OPEN_QUIET_MS` / `_SHORT_MS`）**：定稿到达时看「截至此刻的
连续静音」，不够就等。定稿本身已经晚于停嘴 `commit→定稿`（~260 ms），所以多数
轮次不花时间；它只在「用户确实又开口了」时生效。300/200 是起点（p ≥ 0.8 走短档），
400/250 会把相邻两句并成一句。

**一个已经踩过的实现坑**：门槛里用 `await takeProbability` **之前**拍的 `evaluatedAt`
算静音，会在判停那趟往返（70–200 ms）里算出**负数**（日志里出现过「静音才 −55 ms」），
门槛等于失效。必须取「此刻」。

**300/200 不是拍的**：公开中文基准（`livekit/eot-bench`）里 755 个句中停顿给的曲线是
「300 ms 挡住 43.2% 的换气（= hold 的 p50）、还有 56.8% 会漏过去」。
再往上抬买到的是递减的：500 ms 挡住 71.3%、800 ms 挡住 90.2%。
代价不是「每一句都硬多等 Δ」：离线 `eot` 段的 duration 是**录音截断点，不是句尾属性**
（别拿它算「推迟率」）；真机上也只有在**静音超过链路窗口**的轮次上才会被听见 ——
整条链路从定稿到出声 p50 **1328 ms**（[EOT-SUPPLEMENT.md](./EOT-SUPPLEMENT.md) §10.3），
从停嘴算起约 1.6 s，而 hold 的 p95 只有 1000 ms，所以**约 95% 的句中停顿本来就会在出声前被吸收**。
300 ms 能成立不是因为「躲在 261 ms 的阴影里」，而是因为**整条链路约 1 秒的延迟本身就是免费窗口**。
见 [EOT-BENCH-RESULTS.md](./EOT-BENCH-RESULTS.md) §0（第 1、2 条）与 §3。

**回放噪声**：③（开轮→首块）在 NLS 基线上同样出现 12202 / 11408 的长尾，② 也有 4526 ——
那是回放环境的，不是本改动引入的。单次回放的方差很大，拆句率要多次跑才算数。

## 6. 真机档案 `20261118-124350`（29 轮）：判停的三个病

上生产后第一场（qwen-realtime + commit 40 + 门槛 300/200）的实测，和回放的结论一致，
但把「慢」拆成了三个独立来源：

| 现象 | 数字 | 来源 |
|---|---|---|
| **打满延伸上限**的轮次 | **7 / 29**（8 次判决） | p 在中文上系统性偏低 |
| `p < 0.2` 的判决 | 44 次（只有 4 次最终 accept） | 模型 |
| 门槛（`why=silence`）挡下的等待 | 60 次 / 合计 **12.7 s** / 中位 235 ms | **按设计**（拿时间换不拆句） |
| `why=grace` 的等待 | 8 次 / **3.2 s**，其中一半是假的 | **真 bug**（见下） |

**p 在中文上不成立**（完整句也被判「没说完」）：

```
「帮我算一下。」         p = 0.006
「我的手机号是幺三八。」  p = 0.011
「我让你挂断。」         p = 0.023     ← 完整祈使句
```

这和 eot-bench 的 AUC 0.754 是同一件事：**模型在「完整短句」上系统性偏低**，调参救不了。
但「只能换/训模型」这个结论**已被推翻**（2026-11-18）—— 同一批真机录音上，
真正的问题是有 40% 的轮次被 `unsure`/`unfinished`/`grace`/`short` 拖过，
其中非 silence 三条的等待 **88% 是白等**；砍掉它们之后 `②` 的 p50 从 548 ms 掉到 100 ms，
没有动模型（[EOT-SUPPLEMENT.md](./EOT-SUPPLEMENT.md) §9、§10）。

**门槛救不了「慢速念数字」**：人念手机号时数字间停顿 300–800 ms，而门槛是纯静音 300 ms，
于是「我的手机号是 138…」被拆成 3–4 轮。eot-bench 早就预告过（300 ms 只挡 57% 的
句中停顿），LiveKit 也把地址/电话/卡号列成最难 case —— 同一个原因。

**grace 被同一句的尾巴触发（已修）**：`partialGraceMs` 原本只看时间戳，而
qwen-realtime 在定稿前 6–9 ms 会再发一条**和定稿一字不差**的 partial，句尾静音上还会
吐一个「嗯。」。两种都会被当成「用户还在说」，各白等一拍：

```
+33701 partial '等于多少？'   ← 与定稿相同
+33801 judge p=0.978 extend/grace wait=400
+34242 partial '嗯'          ← 旁听反馈
+34274 judge p=0.952 extend/grace wait=400
```

现在 `partialIsNew()` 按文本判断：去掉标点后 partial 既不等于定稿、也不是它的前缀、
也不是纯语气词，才算新内容。配套把 `TURN_JUDGE_EXTEND_MS` 400→200、
`TURN_JUDGE_MAX_EXT` 7→2、`TURN_JUDGE_MAX_UNSURE` 2→1（真机 4 次延长才收下是常态，
2.8 s 的总预算没人受得了）。

> **后续（2026-11-18，`ed87bc7`）：整条 grace 已删除。** 上面那次「按文本判断」只是让它
> 少白等，数完 87 次 extend 之后发现它**命中 0/8、白等 3200 ms** ——
> 连同 `unfinished`（0/3）一起砍掉，`partialIsNew()` / `isBackchannelOnly` 的引用也随之移除。
> 验收见 [EOT-SUPPLEMENT.md](./EOT-SUPPLEMENT.md) §9–§10。




## 7. 幽灵文本：静音上幻觉出的短句（2026-11-23）

服务端在**我们喂进去的静音帧**上会解出短句。八份真机档案里出现的全部是：
`Thank` / `Thank you.` / `Yeah.` / `Okay.` / `Oh.` / `These.` / `ж.` / `die.` / `エピ。`

它不只是脏数据，会**打断播放**：`partial` 一旦解出 ≥2 个字、且状态是 `speaking`，
`DialogFsm.bargeIn()` 就成立，紧接着 `audio.stop` 清掉设备缓冲。

```text
91351  "Thank"  上行 RMS −75.6 dBFS（静音）  垫话 1.28 s 只播到 0.64 s，dsh 答案没合成
260134  "Thank"  上行 RMS −71.8 dBFS         答案首块刚发出 30 ms，6.72 s 音频被清空
```

### 7.1 判据不是语种（试过，被数据否掉）

「无汉字即丢」看着能一刀切，两个方向都不成立：

- **误杀**：英文短句、设备名是合法输入；
- **漏放**：同样是 `Thank`，251456 那次底下是 **−24.4 dBFS 的真实语音** ——
  用户确实在说话，ASR 把第一版认成了英文。`ж`(29.6) / `die`(−28.7) / `These`(−27.9) /
  `Oh`(−30.8) 也一样，都在真实语音电平上。

静音幻觉和「真实语音被认错」是两件事，**语种分不开它们，有声/无声才分得开**。

### 7.2 判据：距上次有声帧多久

`UtteranceAssembler` 本来就按能量门算停嘴时刻（`lastVoicedAt`，与设备标定同源），
两侧差得很开：

| 场景 | 距上次有声帧 |
|:---|:---|
| 真插话（`你看过` / `飞向` / `哈喽`） | 0–120 ms |
| 静音幻觉（91351 / 260134） | 885 ms / 2.7 s |

取 **500 ms**，实现在 `src/barge-voicing.ts`，闸在 `VoiceConnection.onPartial`
（只在 `speaking` 时生效）。没有音频证据时（`lastVoicedAt = -Infinity`，模拟器）
**放行** —— 按静音处理等于把插话功能整个关掉。

### 7.3 定稿管不了（别在这里加）

定稿的 gap 两边重叠，分不开：真实句 240–400 ms（p50 ~300），幻觉句 325 / 352 / 386 ms。
拿它拦定稿会误杀正常句子，所以这条只管插话；幽灵**定稿**（`Okay.` 开一轮）仍未处理。
