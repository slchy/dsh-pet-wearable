## 0. 结论先行

1. **③（agent + TTS）是首要项**，占总量 **43–62%**；三场都是当年最大段。
2. **③ 里面 agent 是主因，不是 TTS**：agent 自报 p50 367–1068 / p90 1080–1950；
   而「③ − agent」（进程开销 + TTS 首包）三场稳定在 **p50 293–302 ms / p90 399–580 ms**。
   → **优化 TTS 首包的天花板只有 ~300 ms；治 ③ 必须治 agent。**
3. **① 已经很紧**：p50 311–367、p90 377–447，三场没有恶化。**不值得再动。**
4. **② 出现回退**：p50 从 **5 ms（11-17 22:10）→ 325 ms（11-18 20:43）**，
   p90 从 956 → **2121**。成因是 `judge.decide` 里 **`why=silence` 60 次共 12.7 s**，
   而上一场是 **0 次**。
5. **② 的尾巴不在 QoS 预算内**：静音闸门那条 `return` 不检查 `overBudget()`，
   所以 `TURN_JUDGE_WAIT_BUDGET_MS` / `SEQUENCE_MS` 管不到它（代码见 §3.2）。

## 4. ② 的回退：`why=silence` 是新增的

`judge.decide` 按 `why` 汇总 `extend` 的等待：

| 档案 | silence | unsure | grace | unfinished | short |
|---|---:|---:|---:|---:|---:|
| `20261117-221010` | **0 ms / 0 次** | 3200 ms / 8 | — | — | 400 ms / 1 |
| `20261118-124350` | **12704 ms / 60 次** | 2800 ms / 7 | 3200 ms / 8 | 750 ms / 3 | — |

`silence` 是**静音闸门**（`openQuietFor()`：`quietNow < openQuiet` 就等）。
它在 `221010` 里一次都没触发，在 `124350` 里成了最大项。

每轮 judge 等待合计：`221010` p50 **0** / p90 800 / max 800；
`124350` p50 **250** / p90 **1673** / max 2075。

### 4.1 这些轮次是什么内容

② 超 500 ms 的轮次，文本几乎全是**数字串/短碎片**：

```
#9  我的手机号是幺三八。    #12 我的手机号是幺三八。   #13 面二五三六。
#15 我的手机号是。          #16 二三五零。              #23 怕。
#25 让你去。                #29 我让你挂断。            #6  等于多少？
```

正是 `looksUnfinished()` 判为「像没说完」的形态。而这些轮次拿到
`maxExtensionsNow()` 的**序列豁免 → 12 次额度**，于是静音闸门可以连续触发 5–6 次。

**这不是纯粹的坏**：用户念号码时中途换气，等下去是对的（不等就会把半截号码送去回答）。
问题是它**没有上限**，也不受 QoS 预算约束。

### 4.3 但 `②` 的绝对值 ≠ 首字收益（`flush` vs `agent-bound`）

`124350` 轮 11 是最干净的反例：`② = 337 ms`、首声 **954 ms**，和直接放行的那几轮
（950–1100 ms）持平 —— 多等的那 337 ms 完全藏在链路里，一分钱没花在首字上。
补证 §10.3 把 54 轮逐轮分了类：

| 类 | 轮数 | 截短 `②` 能不能省首字 |
|---|---:|---|
| `agent-bound`（`llm.first` 明显晚于开轮） | 39 | **不能** —— agent 才是瓶颈，`②` 藏在它后面 |
| `flush`（`llm.first` ≈ 开轮，回复被 accept 卡住） | 10 | 能 —— `②` 全暴露在关键路径上 |
| 缺仪表（无 `llm.first` / 无 `tts.first`） | 5 | 判不了 |

所以**别把 `②` 的缩短直接读成「首字快了」**：上面那 39 轮在真机上根本感受不到。
要动首字得动 ③（agent + TTS）。

### 4.2 代码依据（`src/utterance-assembler.ts`）

```ts
// L827：静音闸门
if (openQuiet > 0 && this.extensions < this.maxExtensionsNow()) {
  const quietNow = this.now() - this.lastVoicedAt;
  if (quietNow < openQuiet) {
    const wait = Math.max(1, Math.min(openQuiet - quietNow, this.options.extendMs));
    this.extensions += 1;
    this.waitedMs += wait;
    ...
    return;              // ← 没有 overBudget() 判断
  }
}
```

对比收下判据（L900 附近）是**有** `overBudget()` 的：

```ts
if (probability >= threshold
  || this.extensions >= this.maxExtensionsNow()
  || this.overBudget()          // ← 只有这一条路会检查预算
  || this.unsureExtensions >= this.maxUnsureNow())
```

而 `maxExtensionsNow()` 在序列形态下返回 `max(maxExtensions, 12)`：

```ts
const sequence = this.options.waitBudgetSequenceMs ?? 0;
if (sequence > 0 && looksUnfinished(this.pendingText)) {
  return Math.max(this.options.maxExtensions, 12);
}
```

**后果**：`TURN_JUDGE_WAIT_BUDGET_MS=400` / `TURN_JUDGE_SEQUENCE_BUDGET_MS=1200`
只封住「收下」的判定，封不住静音闸门的重复等待 —— 实测 ② 达 **2264 ms**，
已超 1200 ms 的序列预算。

> ⚠ 这一条是观察，**不是建议改动**。要不要给静音闸门加预算判断，涉及
> 「念号码时宁可多等」与「别让玩家干等 2 s」的取舍，需先定策略。
>
> ✅ **已定并已改**（`ed87bc7`，2026-11-18）：闸门纳入 `overBudget()`、
> 序列形态的那条 12 倍豁免删除、并新增一条谁都不能绕过的统一上限
> `TURN_JUDGE_MAX_OPEN_SILENCE_MS`（默认 650）。真机 4 场 54 轮重放验收见
> `docs/EOT-SUPPLEMENT.md` §10：② p50 548→100 ms、p90 2221→1346 ms，
> 但 39/54 轮 agent 比等待更慢，**② 不是主延迟项**。

## 5. 该治哪里（按收益排序）

| 顺序 | 项 | 现值 | 可控空间 | 代价 |
|---|---|---|---:|---|
| 1 | **agent（③ 内）** | p50 367 / p90 1950 | 大 | 换模型/压 prompt/流式切句，属于 `dsh` 侧 |
| 2 | **② 的静音闸门尾巴** | p90 2121（超预算 1200） | ~~大~~ **已治** | 见上：闸门纳入预算 + 统一上限（`ed87bc7`）；真机重放 ② p90 2221→1346，代价是 2/54 轮被接话 |
| 3 | TTS 首包 | p50 ~293（③−agent） | 小（≤300） | 已接近下限 |
| 4 | ① 判停+ASR | p50 311 / p90 377 | 很小 | 已紧，不建议动 |

**与 `docs/EOT-SUPPLEMENT.md` 的关系**：那边量的是「换模型对误切率的影响」，
这边量的是「时间花在哪」。两者在 ② 上交叉：`why=silence` 与 `why=unsure`
既是延迟来源，也是误切防护。所以 **换判停模型不会缩短 ② 的尾巴** ——
那 12.7 s 主要是闸门在等用户真的静下来，不是模型在犹豫。

## 6. 已知口径限制

1. **`124350` 的 `gate.close` 没有 `gapMs`**（旧格式）→ 2/29 轮的 ① 为负，
   停嘴时刻只能取记录时刻（比真实停嘴晚 `holdMs`），**首字延迟被低估**。新档案已有 `gapMs`。
2. **`extendMs` 在 `124350` 里是 400**（`grace` 3200/8、`unsure` 2800/7 都是 400/次），
   与后来下调的 200 不同 → 那场的 ② 尾巴含旧配置的放大。
3. 样本量：8 / 13 / 29 轮。p90 在 8 轮上等于最大值，不可当分布看。
4. `③ − agent` 不等于 TTS 首包：文本边生成边送 TTS，实测 `tts_first_ms`（p50 503）
   有时反而大于 `③ − agent`（p50 293），两者是**流水线并行**，不能相加。
