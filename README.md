# dsh-pet-wearable

**面向智能穿戴设备的云端全双工语音 Agent（基于 `dsh`）。**

穿戴端仅负责音频采集与播放、拍照及设备状态上报，ASR、判停、推理与 TTS 全部在云端完成。对话分两层：短句闲聊由快车道直接答（首字 ~0.5 s），其余交给 `dsh` 做多步推理与工具调用，中途随时可打断。同时支持有节制的主动开口，并通过握手阶段的能力协商实现设备无关——接入新型号硬件无需改动核心代码。

## 「pet」指什么

这里的 `pet` 指的是**行为层面的在场感与适度主动性**，而非桌面像素宠物、动画或固定人设（角色语气与习惯完全由提示词定义，可随时替换）。

> 人设目前有**两份**：`dsh` 用 [mcp/profile.cordis.yml](./mcp/profile.cordis.yml)，快车道有自己一份系统提示词（`src/fronted-agent.ts`），改人设要两边都改。

区别于传统唤醒词工具「叫了才应」的交互方式，全天候穿戴设备更适合一种低存在感的伴生形态：

* **持续在场感知**：结合佩戴状态、剩余电量与深夜时段判断当前是否适合交互。
* **双向对话主动权**：以用户随时开口为主导，系统仅在合适时机受控地主动搭话。

## 硬件适配与设计原则

接入新设备（如[雷鸟 X3 Pro](./docs/devices/RAYNEO-X3-PRO.md)）不需要修改本仓库代码。针对穿戴硬件的典型约束，系统在协议与算法层做了以下适配：

* **能力协商与降级**：设备在 `Hello` 握手中声明自身能力（是否支持免手拍、音频采集、能量/佩戴状态上报等），插件不绑定具体型号。能力缺失时自动降级（例如不支持免手拍则不主动触发拍照）。

* **远场低电平拾音**：针对实测底噪 `-60…-51 dBFS` 的穿戴麦克风，采用上行增益 + 能量门（`-40 dBFS`）+ 基于音频特征的语义判停（Smart Turn），不依赖固定静音时长切分。

* **插话与打断**：ASR 的中间结果或定稿一到（旁听反馈如「嗯」除外）就打断，不靠关键词匹配；打断只在**正在播**时成立（`DialogFsm.bargeIn` 仅 `speaking`），立即下发 `audio.stop`、作废排队中的轮次，并把没播完的片段留给下一轮判断要不要补。

* **低功耗与弱网恢复**：端侧不运行 ASR、TTS 或推理模型；低电量时自动抑制主动开口。网络断开重连后自动对齐会话状态，并补播断线期间完成的后台任务结果。

## 快速开始（零密钥本地跑通）

无需连接真机或配置任何 API Key，使用内置的 `canned` 识别、`silent` 合成与 `echo` agent 即可跑通完整链路：

```bash
npm install
node src/main.ts --listen 8766 --stt canned --tts silent --agent echo
```

在另一个终端模拟设备推流音频：

```bash
node tools/fake-phone.ts --port 8766 --sbc tmp/voice.sbc
```

如需验证**主动开口**逻辑（纯虚拟时间运行，零网络、零密钥、零 `ffmpeg` 依赖）：

```bash
npm run sim                           # 运行声明式场景
npm run sim -- --explore --runs 500   # 随机探索，检测不变量违反
npm run sim -- --trace out/           # 导出 JSONL 格式时间线
```

> **真机与生产环境依赖**：接入真实硬件需安装 `ffmpeg`（用于 mSBC 解码）并配置至少一家 STT/TTS 供应商；运行真实对话需接入 `dsh`（非本仓库直接 npm 依赖，默认走 headless，加 `--dsh-sdk` 换 SDK 形态）。生产接法是直连 TLS + `MIAI_TOKENS` 鉴权，见 [OPS-RECORD](./docs/OPS-RECORD.md)。

## 系统架构

```
端侧（眼镜 / 耳机 / 手机）              云端（本仓 src/）

  AudioRecord / AudioTrack  ────────►  tls 连接（帧 · 鉴权 · 心跳）
  Camera2 / 佩戴 / 电量 / 触摸  ─────►          │
                                               ▼
                               能量门 → ASR → 判停（UtteranceAssembler）
                                               │ 整句
                                               ▼
                               DialogFsm（话筒 · 轮次票据 · 一轮一停）
                                               │
                                 ┌─────────────┴─────────────┐
                                 ▼                           ▼
                         快车道 FrontedAgent          dsh（工具 / 后台 Job / 子代理）
                           短句闲聊直接答              任务、事实、带图
                                 └─────────────┬─────────────┘
                                               ▼
                                   TTS（CosyVoice）→ PCM 下发
```

架构遵循三条核心原则：

1. **设备无关**：`src/devices/` 仅定义标准原语（6 个下行操作、6 个上行事件及一份能力声明），通过握手协议动态适配硬件。

2. **组件可替换**：STT、TTS 与 agent 都通过工厂契约注入（见 [src/providers.ts](./src/providers.ts)），无密钥时自动回落离线实现。换上新的 STT/TTS 只需一个实现文件加一个装配分支，业务逻辑不动；agent 走同一契约，但内置实现绑定 `dsh`。

3. **逻辑可单测**：时机判定、判停、打断与绑定策略均抽离为不依赖 Socket 的纯函数，由 `npm test`（当前 519 条用例）与假设备线协议测试完整覆盖。

各台状态机（`DialogFsm` / `FloorArbiter` / `PetBrain` / `UtteranceAssembler` / 快车道 / 播报队列）的状态、驱动方与「唯一真相」表见 [state-machines](./docs/state-machines.md)。

## 全双工与后台调度

* **快慢两层**：短句闲聊由快车道（`FrontedAgent` + 快模型）直接答；任务、事实、带图的句子交给 `dsh`。默认**投机**——两边同时起跑，快车道先给出实质文本就用它并掐掉在途的那一轮 `dsh`；判不出（本地判据否决 / 暗号 `[[DELEGATE]]` / 超时 / 空答复）才整段让给 `dsh`，并**先给用户一句回执**（「我看看。」）填掉中间那 1.8–2.9 s 的安静，答案一到就顶掉回执并清设备缓冲（`FAST_LANE_SPECULATE=0` 退回串行）。插话会把上游一起取消，不只是停喇叭。

* **非阻塞执行**（`dsh` 侧，规则在 [mcp/profile.cordis.yml](./mcp/profile.cordis.yml)）：前台命令只等很短一会儿，超时自动转后台 Job 并立刻把 job id 还回来；要判断、要多步的活派给 Subagent。主对话因此不被长任务占住。

* **话筒只有一份真相**：仲裁在 `AppSession.floor`（[src/app/session.ts](./src/app/session.ts)），宠物只申请不仲裁。它是一张**抢占表**而不是严格优先级队列：

  | 占用者 | 可被谁抢 |
  |---|---|
  | `user` | 无（用户永远优先） |
  | `reply` | `user` |
  | `announce` | `user`、`reflex`（**抢不动 `reply`/`pet`**：正题没说完不插播） |
  | `pet` | `user`、`reflex`（`announce` 不抢，等它播完） |
  | `reflex` | 任何人（`user` 除外） |

  占用/释放由 `DialogFsm` 的状态转移驱动，一轮结束话筒自动放空。

* **后台汇报让路**：任务完成后的播报**不属于任何一轮**（走旁白通道，不占票据、不改状态机），开口前过四道闸：没有正题在跑 → 用户安静 ≥ 800 ms → 开麦后复查（这期间用户说了一整句就排回队首，不是丢掉）→ 出声后被打断则停下并把没念完的部分交给下一轮判断。纯语气词（「嗯」）不算打断。

## 主动开口机制

主动开口并非定时轮询，而是一个基于多维上下文的**时机状态机**（详见 [ADR-0001](./docs/adr/0001-app-layer-and-pet.md)）。每次触发前均会评估佩戴变化、电量、深夜时段、环境安静时长、话筒占用状态以及最小发言间隔。

默认策略偏向克制。如需提高交互频率，可调小 `chatterAfterIdleMs`，**建议通过参数调优而非叠加新规则**，以保持行为的可解释性。

在独立进程模式下，主动开口默认关闭，需设置环境变量 `PET_PROACTIVE=1` 开启（启动日志将输出当前开关状态）。注意 `AppSession`（持话筒仲裁，对话环自己要用）**总是构造**，关掉的只是宠物环 `PetSession`。

回放前后对比（同一份源音频，同一条隔离 harness）：

| 配置 | 停嘴→ASR | 出句→开轮 | 开轮→首块 | **停嘴→首块** |
|---|---|---|---|---|
| 改前：`deepseek-chat` + 判停宽限 400 + 静候 150（源档案当时） | 572 | 151 | 1583 | **2306** |
| 改后：`qwen-flash` + 宽限 150 + 静候 0 + 判停提前 + 预热 + 丢句首静音 | 373–403 | **2** | 900–1005 | **1367–1427**（单场）／**1408**（8 场汇总 p50） |

改后那行的单场值是 2026-11-17 现行代码连跑 4 场的范围；**汇总 8 场 21 轮是 p50 1408 / p90 1652**，所以别拿单场最小值当结论 —— 8 场里模型首字（TTFT）从 314 摆到 588，光这一项就 ±270 ms，比任何一版代码改动都大。三条与模型无关的改动各管一段：

- **判停宽限**（`SMART_TURN_PARTIAL_GRACE_MS`，400→150）：原来「音频停了但 ASR 还在出字」的防抢话闸**几乎每轮都触发**、每次白等一整拍 475 ms。收到 150 后仍挡得住正常 partial 间隔，回放里 ASR 逐字一致、轮数不变。② 由 622–625 降到 137–148。
- **静候窗**（`SMART_TURN_QUIET_MS`，150→80）：定稿后再等一会儿，判停器看的是累积音频，不依赖这段长度。
- **判停前起跑**（`FAST_LANE_PREFETCH=0` 可关）：句子定稿时文本已定，判停只决定要不要并下一段，所以那一刻就把这一句问出去。A/B（背靠背两场）：开轮→模型首字 **277 ms**（开）vs **500 ms**（关）。
- **丢句首静音**：CosyVoice 第一块是「~120 ms 数字静音 + 起音」的混合块，按整块判静音会被语音拉高、静音跟着推给设备。现在块内按 5 ms 窗口裁（−45 dBFS 以下），下行开头静音 **146 ms → 11 ms**。
- **中间结果投机**（`FAST_LANE_PARTIAL_SPECULATE=0` 可关）：ASR 的 partial 比定稿早 p50 **731 ms**（真机 47 轮），所以**静音那一刻**就拿最新那版先问出去。定稿到达时确认「它是定稿的前缀 + 覆盖 ≥60% 长度 + 没把数字截断」才认领，确认不了就作废、退回定稿后再问 —— 所以**不改正确性**，坏情况下只多花一次请求。合成音频单轮 A/B（同一份 PCM、背靠背两次）：③ 开轮→首块 **1036 → 838 ms**，认领时模型已经跑了 136 ms。为什么只在静音那一刻发、不是每版 partial 都发：收益在「答案赶在定稿前出来」就**饱和**了（模型首字 ~290 ms ≪ 731 ms），提前更多不省时间，只是多花钱；而且静音了才说明用户真停了，这一版离定稿最近，长度闸门才判得准。
- **修「预跑认领后增量丢失」**（`2ce0e21` 引入，已修）：`startPrefetch` 存的是 `{ ...slot }` 拷贝，而 `ask()` 的回调闭包捕获的是原对象 —— 认领时 `listener` 只装在拷贝上，**认领之后到达的增量全堆进 `buffered` 没人取**。后果是快车道只把「认领前攒下的那几个字」送去合成：轻则**话被截断**（生产 3 天 19 个快车道轮里 9 轮出现「实际念了」，即只播了一部分），重则一个字的没收到 → `合成失败` → 退回整段合成（多付 300–500 ms）。改成存同一个对象后，同一份回放 ③ p50 **1048 → 769 ms**、`合成失败` 2 次 → 0 次。这条是「仪表没到位时的典型症状」：日志只说「合成失败」，不说是谁没送文本。
- **TTS 对冲（试过，已回滚）**：同一句并发跑两路取先到的音频，端到端 **p50 反而慢 ~45 ms**（两批复现同向：关 982／981，开 1022／1032，每批 n=8）。单独量首包也只从 557 降到 536（对 p90 有效：640→566），没量到的部分补不回来 —— CosyVoice 的首包是**服务商侧共享容量排队**，双份只是抢同一个坑位。代价却是双份合成费 + 一套「落败那路怎么弃」的异步收尾（`gen.return()` 在生成器挂在 `await` 上时是排队的，只能靠关连接取消），不值得。LLM 那边能对冲出 −50 ms 是因为它抖在「哪台机器空着」。

注意「停嘴→首块」量的是**协议首块**；裁掉句首静音之后它才等于「用户听到第一个字」——之前那 146 ms 设备是在播数字静音。

`bench/fast_lane`（模型层，n=13）：整句 p50 346 / p90 455，首字 p50 **259** / p90 **360** ms，误拦截 0/10，闲聊命中 13/13。注意这是**模型首字**，比上表的「停嘴→首块」少掉 ASR、判停、TTS 三段，两个口径不能混着比。

剩下的地板：ASR 判句静音 200 + 链路 ~200、判停 ~140、模型首字 ~300、TTS 首包 ~350。

**判停前起跑**（已做，`FAST_LANE_PREFETCH=0` 可关）：ASR 一句定稿时文本就定了，判停只决定要不要并下一段，所以那一刻就先把这一句问出去。A/B（同一份音频、同一条 harness、背靠背两场）：开轮→模型首字 **277 ms**（预跑开）vs **500 ms**（预跑关）—— 判停那一拍里模型已经跑了 140–153 ms（日志 `认领预跑（已经跑了 N ms）`）。并段时把这一轮作废、按并完的文本重问，用户只会听到一句。

并段这条路是**用 TTS 造音频验的**（`bench/replay/README.md` 里有配方）：TTS 合成「你好呀」+205 ms 静音+「说」拼成一段上行，把 `SMART_TURN_THRESHOLD` 抬到 0.99 逼出判停的「没说完」分支 → 日志按顺序出现 `判停前先问出去 "你好呀。"` → `预跑作废（判停并了段…）` → `判停前先问出去 "你好呀。说。"` → 只答一次。默认阈值下这两段会被各自收成一轮（判停器判 0.98 说完），所以**并段本身不常发生**，它只是「判停说没说完」时的兜底。

真机端到端（2026-11-16 01:46，v2 设备 `04:34:…`，9 轮，音频回放 + 会话档案逐轮对齐）：

| 用户说 | 停嘴→开轮 | 开轮→首块 | **停嘴→首块** | 走的哪条 | 模型首字 | TTS 首块 |
|---|---|---|---|---|---|---|
| 来和我随便聊一下。 | 998 | 1044 | **2042** | 快车道 | 499 | 543 |
| 没啥事儿。 | 504 | 914 | **1418** | 快车道 | 508 | 406 |
| 嗯，是的。+辣椒炒肉。 | 328 | 1271 | **1599** | 快车道 | 804 | 468 |
| 嗯，我去睡觉了。+再见。 | 合并 | 1088 | **980** | 快车道 | 562 | 524 |
| 你最近怎么样呢？ | 529 | 1254 | **1783** | dsh（本地判据） | 675 | 578 |
| 你好。 | 1226 | 1708 | **2934** | dsh（快车道首字超时 1200） | 1245 | 460 |

读法：**端到端 ≈ 判停收敛(350–600) + 开轮(150–1000) + 模型首字(500–800) + TTS 首块(290–580)**。快车道命中 4 轮 p50 ≈ `1.5 s`；交给 dsh 的那轮 `2934 ms` 正是「回执」要填的空白（首字超时要等 1200 ms 才判让位）。「停嘴」以 `gate.close.t − gapMs` 为准；`你把眼睛挂断一下。` 那轮会话结束得比 gate hold 还早，**缺仪表，不补估**。这张表是**改前**的基线，留着当对照；改后的数字见上面那张回放对比表。

可调的旋钮（都在 `src/main.ts` 读环境变量，改完重启即可，不必重新编译）：`SMART_TURN_QUIET_MS`（定稿后静候，默认 80）、`SMART_TURN_PARTIAL_GRACE_MS`（判停宽限，默认 150）、`SMART_TURN_EXTEND_MS`（每次延长，默认 400）、`SMART_TURN_MAX_EXT`（延长上限，默认 7）；快车道侧 `FAST_LANE_MODEL` / `FAST_LANE_BASE_URL` / `FAST_LANE_API_KEY` / `FAST_LANE_HEDGE`（默认 2，对冲份数）/ `FAST_LANE_PREFETCH` / `FAST_LANE_PARTIAL_SPECULATE`；TTS 侧 `COSYVOICE_MODEL` / `COSYVOICE_VOICE` / `COSYVOICE_EMOTION_MODE`。

排查用可复算的日志脚本：`scripts/latency-report.ts` 逐轮分段统计，`scripts/dsh-timeline.ts` 对齐 `dsh` 会话日志拆解 Agent 内部耗时。**全仓脚本的路由表与口径归属见 [docs/TOOLS.md](./docs/TOOLS.md)** —— 算延迟/审计状态轮转之前先查那张表，别另写一个（踩过：手搓的分段脚本把 ② 算成 63543 ms）。

**时序与状态轮转审计**（bench 的主要出口，不是任务做没做成）：`node --experimental-strip-types scripts/fsm-trace-check.ts <档案>` 审一份会话档案 —— 轮次是否配对、状态转移是否只走白名单、`tts.first` 是否落在 `speaking` 里、插话有没有真的发 `audio.stop`、停嘴到首块/单轮时长是否超预算。规则与依据见 [state-machines §5.8](./docs/state-machines.md)。`bench/replay` 和 τ² bench 跑完都会自动审一次。

## 配置与部署

两种形态的配置面不同，别混着看：

- **独立进程**（`node src/main.ts --listen 8766`）：命令行参数 + `MIAI_*` 环境变量
  （`MIAI_STT` / `MIAI_TTS` / `MIAI_AGENT` / `MIAI_TOKENS` / `MIAI_TLS_KEY` / `MIAI_TLS_CERT` …），
  供应商密钥走各自的环境变量。完整说明见 [docs/OPERATIONS.md](./docs/OPERATIONS.md)。
- **`dsh` 插件**（`driver.ts`）：下面这张表，是插件 schema 的实际默认值。

| 配置项 | 默认值 | 说明 |
|---|---|---|
| `port` | `8766` | 设备接入监听端口 |
| `host` | `127.0.0.1` | 绑定地址；**监听非本机地址时必须同时配置 `tls` 与 `auth`**，否则拒绝监听（见 [bind-policy.ts](./src/bind-policy.ts)） |
| `tls.keyPath` / `certPath` | `''` | TLS 证书路径，须成对配置或同时留空 |
| `auth.tokenFile` | `''` | 设备鉴权 Token 文件，请使用 `npm run pair -- new` 生成，勿手动拼写；留空 = 不鉴权，此时只能绑本机 |
| `device` | `''` | 仅 v1 手机的型号提示（如 `xiaomi-glasses`）；v2 设备在 `Hello` 里自报能力，不用填 |
| `voice` | `''` | TTS 音色；**留空 = 用 provider 自己的默认值**（换 TTS 就换一套名字，插件不替它决定） |
| `turnThreshold` | `0.5` | 语义判停阈值，调高更不容易被判为说完 |
| `proactive.*` | 见 [driver.ts](./src/driver.ts) | 主动开口的时机参数（`chatterAfterIdleMs` / `minProactiveGapMs` / 深夜时段 / 低电量阈值），默认一律偏向「宁可少说」 |

`dsh` 的人设与 agent 规则在 [mcp/profile.cordis.yml](./mcp/profile.cordis.yml) 里（快车道那份系统提示词在代码里，见上文「pet 指什么」）。本地跑起来之前先把它装到 `dsh` 的 profile 上，否则你面对的是一个**没有任何人设**的通用 agent，行为和线上完全不同：

```bash
npm run install-profile      # 拷到 ~/.dsh/profiles/sdk/cordis.patch.yml
```

> **Patch 语义提示**：配置补丁中裸条目默认按 `id` 覆盖；新增节点必须写在 `insert:` 字段下，否则会触发 `entry not found` 错误。

## 明确边界（Out of Scope）

* **不做视觉形象**：不开发像素风界面、动画或虚拟人物形象，已有成熟开源方案覆盖该方向。

* **不支持单会话多设备同时在线**：严格遵循「一副设备对应一个会话」的模型。

* **不造形式化主观指标**：交互自然度以实际盲测体验为准，不为「拟人感」强行设计量化打分体系。
