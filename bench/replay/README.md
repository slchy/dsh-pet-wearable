# 真机向量回放

把**真机会话录下来的上行音频**原速喂回云端，逐轮对比 ASR 与延迟。

```
python bench/replay/run.py --list                       # 看有哪些向量/档案
python bench/replay/run.py --archive <会话名> --turns 3   # 回放前 3 轮
python bench/replay/run.py                              # 用向量库里最新的一份
```

## 为什么是它（而不是 E2E）

真机档案里每场会话都留着：

| 文件 | 内容 |
|---|---|
| `uplink.pcm` | 解码后的 PCM16 16 kHz、**放大前**、从连接建立起连续写 |
| `events.jsonl` | `gate.open` / `gate.close` / `asr.sentence` / `turn.start` / `tts.first` / `turn.end` |

所以「用户说了什么」是**真机真录**的：真实口音、真实噪声、真实停顿、真实打断。
同一份向量可以反复喂 —— 改一次代码跑一次，逐段对比，不受说话人当天状态影响。

E2E（手机喇叭 + 麦克风）只在两种情况下用：没有历史录音、或者要验声学通路本身。
它慢得多、受房间与音量影响，而且素材是合成音。

## 两种回放

| 模式 | 干什么 | 用在哪 |
|---|---|---|
| `--mode utterance`（默认） | 一轮一轮：只放用户说话那一段，等回复念完再放下一轮 | **回归对比**。源档案每轮 ↔ 回放每轮一一对应，①②③ 可以逐条比 |
| `--mode stream` | 整段上行原速重放 | 验打断/旁白这类**跨轮交织**的行为。注意它不可逐轮对账：回复变快之后，原本"用户插话"的那句会变成"干净的新一轮"，轮次结构就变了 |

## 向量库（重要）

回放本身会产生新档案，而服务器 `MIAI_ARCHIVE_KEEP=20` 是滚动删除的。
**踩过**：回放一场 12 轮的真机会话，把它自己挤掉了 —— 工具吃掉了唯一那份输入。

所以第一次用某场档案时，脚本会先 `cp -r` 到 `~/miai-vectors/`，之后**只从向量库读**。
也可以只钉不跑：

```
python bench/replay/run.py --pin --archive <会话名>
```

## 量什么

全部来自**服务端档案**，客户端只负责按原速送音频：

| 段 | 定义 |
|---|---|
| **①** | 停嘴（`gate.close.t − gapMs`）→ `asr.sentence` |
| **②** | `asr.sentence` → `turn.start`（判停决策 + 开轮） |
| **③** | `turn.start` → `tts.first`（dsh + 上游首 token + TTS 首包） |

默认连 `127.0.0.1`（脚本把客户端 scp 到服务器上跑），把公网抖动摘掉；
要比线上真实延迟就 `--host <服务器地址>`。

## 两个照着调过的细节

**起点要往前多带 2 s。** 判停器看的是"最近这一整段波形"；源档案里它手上有会话
开始到当下的全部音频，只给 300 ms 前导会让它判"说完了"的概率偏低 —— 实测第一轮
② 从 150 变成 622（多等一拍）。

**尾巴给 800 ms 静音。** 判停器靠句尾静音判断说完；切在字上它同样会多等一拍。
这段静音落在 `gapMs`（约 2 s）里，不会把下一句带进来。

## 副作用

回放会**真的把这些轮次跑完**，dsh 会话里会多出这些对话。想清干净就删
`~/voice-agent/session.json`（下次连接开新会话）。

## 文件

| 文件 | 作用 |
|---|---|
| `run.py` | 编排：钉向量 → scp 客户端 → 回放 → 取回新档案 → 逐轮对比 |
| `client.mjs` | 线协议客户端（`audioIn: 'pcm16'`），向量回放与单段 PCM 两种模式共用 |
